## 十、级联停止预算语义修复 ✅(原 P3 ①,升级实施)

**缺陷**:F20 restart 级联停止的 dependent,其退出事件走 `deterministic_death` → `budget.record`——"计划内停止"被计为一次自动重启。依赖反复 restart(人工排障或依赖自身 crash loop)会把健康的 dependent 推向误 Fatal。

**修复**(三层):
1. **FSM** 新增 `on_planned_stop()`:清恢复在途 → `Restarting`,**不计预算、不排程 spawn**(拉回由 F20 依赖门控负责);幂等可重复收口;
2. **eval** `Scheduler.planned_stops` 登记:级联 `signal_stop` 成功即登记;两处死亡入口门控——亲生退出(`on_child_exit` 前 `remove` 分流)与 SCM/liveness 快照缺失(`planned_stops.contains` 跳过 gone 喂食,退出事实由 poll_exit 收口);`dispose_service` 清理(reload 删除/重定义与级联叠加的边缘);
3. **语义边界**:乱序 tick 下 spawn 到点仍有 `deps_satisfied` 二次门控兜底(生产按 svcs 索引序不会乱序)。

**测试**:FSM 级 `planned_stop_does_not_record_budget_or_schedule_spawn`(无 ScheduleSpawn / 无 JournalRestart / 幂等 / 对照 deterministic_death 必计预算)+ eval 级真实进程闭环 `cascade_planned_stop_does_not_burn_dependent_budget`(运行中 dependent 被级联停止 → Restarting 无排程 → 拉回排程 → journal 全程**零** JournalRestart)。

**验证基线(续篇二后)**:223 lib + 7 SCM 集成 + 其余集成全绿;clippy `-D warnings` 零警告;fmt 干净。
