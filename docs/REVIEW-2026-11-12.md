### 8.3 新发现与修复

- F20 有依赖服务每 tick 重复 spawn，产生虚假失败并耗尽预算。已增加亲生 child 与实际依赖证据门控，级联停止与拉回改由真实退出流程驱动。
- 软 reload 只更新外围 policy，FSM 与 PM 仍执行旧值。新增保留水位的策略更新，覆盖 budget、backoff、confirmations、hung_action 与 console。
- 健康恢复的预算事件和 child 退出事件重复计数，activate 失败路径可越过预算。预算记录统一从 FSM 产生，激活失败与验证失败遵循上限。
- reset 清除活 child 的 FSM 身份，后继退出被忽略。使用 reset_with_child 保留身份和启动时刻。
- service/watch 同名时采样与恢复绑定错配。解析顺序与既有绑定对齐，独立 pid:N 检查纳入 watched，非法 PID 在配置入口拒绝。
- 采集线程冻结时重复消费同一高 CPU 快照。process 探测按单调采集代际去重并淘汰陈旧样本，liveness 使用同一单调代际。
- spool 回到内存队列后提前删盘，失败或取消后丢失已落盘事件。产品路径改为成功确认后原子移除。
- spool 取消后的后台 rename 可覆盖下一次运行的新追加。目录级许可随完整阻塞文件事务持有，失败批次轮转避免队首饿死。
- journal/spool 中断写入的半尾行可吞掉后一条记录。新增尾行边界隔离，spool 按字节逐行保留无效 UTF8。journal 读取失败时拒绝启动并保留原件。
- 并发 AlertQueue push 突破容量，投递子任务随取消脱离宿主，deadman 关闭通道忙转。已改为单锁入队、子任务所有权取消及关闭退出。
- 缺省 AgentCfg 与空表默认值不一致，MetricsCfg 默认 interval 为零，Duration 可表示但 Instant 加法溢出，NaN CPU 阈值永久失效。已补默认值、统一时长验证与必要配置边界。
- Windows 安装脚本的 shell 字符串转义与非崩溃错误恢复配置有缺口。改用 New-Service、PSCredential 和 failureflag 1，并补 Windows Service CI。
- 性能脚本全局 pkill 可误伤其他 sleep 进程。改为仅识别并清理本次唯一路径的进程组。

### 8.4 新功能与功能规范

**F21 深度硬件**使用可选 collect-deep-hardware，Linux hwmon、macOS AppleSMC 只读接入，Windows 输出 unsupported。风扇、电压均保留 Option 及机读降级。SMC 采用固定常见键，电压仅接受已核对的定点和浮点编码，并选用 ±100 V 低压供电可信界。该范围是本次实现选择，所有机型的硬件额定值需另外核对。

实机验读发现 VBUS 为 ui32，原始字节 01000000，初实现错误输出 16,777,216 V。已补类型拒绝和回归。最终实测两个风扇约 1345、1461 RPM，VD0R 约 27.79 V，VBUS 为 null 并携带 invalid_data。未经权限的沙箱读取会明确产生 permission_denied，实际硬件值在允许本机只读接口的环境核验。

**孤儿只读接管**将进程身份与可信度持久化。requested 集合证明候选在本轮被查询，collected_at 使用单调时钟防回拨。Pending 与 Attached 阶段保持只读，Fatal 仍可见。确认身份消失后，按最新配置、预算与 backoff 恢复 supervise。

F15 现有范围为 agent 本身的 SCM 服务入口。第五轮将原生 Windows Service 目标恢复混入 F15 的描述已澄清，该目标类型列为后续功能。README、DESIGN、RUNBOOK、deploy 文档、配置示例与 ROADMAP 已按实际代码同步。
